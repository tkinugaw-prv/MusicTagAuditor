# Music Tag Auditor ユーザーマニュアル

クラシック音楽ライブラリのタグ（曲名・作曲家・指揮者・演奏団体など）を検査し、誤りや表記揺れを見つけて修正するためのデスクトップアプリの操作手順書です。

対象読者は、自分の音楽ライブラリのタグを整理したいエンドユーザーです。アプリの実装や内部設計を知らなくても読めるように書いています。

内容の根拠は [README.md](../README.md)・[docs/SPEC.md](SPEC.md)・[docs/TAGGING_POLICY.md](TAGGING_POLICY.md) です。本書とこれらの文書に食い違いがある場合は、それらの文書を正としてください。

## 1. はじめに

### このアプリでできること

- 音楽ライブラリ全体を走査し、タグ付けの原則（[docs/TAGGING_POLICY.md](TAGGING_POLICY.md)）に違反している箇所を検出する
- 検出結果を一覧・差分で表示し、どこがどう変わるかを確認してから適用する
- 見つかった値をその場で正規化辞書に登録し、再検査に反映する
- ファイル一覧から個々のタグを手で編集する（フォルダ単位の一括入力も可能）
- 適用前に自動でタグのバックアップを取り、必要なら復元する

### 最重要方針

**このアプリは「一括で書き換えるツール」ですが、適用前に必ず差分を人間の目で確認できるようになっています。** また、原則に照らして確信が持てない項目は、アプリが勝手に値を埋めることはありません。誤った値で埋めるより、空欄や現状維持のまま保留にして、あとで人間が判断するほうが安全だという考え方に基づいています。

そのため、検査結果には「このまま適用してよいもの」と「人間の確認が必要なもの」が混在します。**チェックが入っていない項目を無理にチェックして適用しないでください。** チェックの既定値には意味があります（詳しくは [5. 検査結果タブ](#5-検査結果タブ)）。

### このアプリでできないこと（v1 時点）

- 音声の再生
- ファイル名・フォルダ名のリネーム
- カバーアート（ジャケット画像）の編集
- MusicBrainz 等オンライン楽曲データベースとの照合
- タグ以外のメタデータ（ReplayGain 等）の書き換え

## 2. 動作環境と起動方法

### 必要環境

- Windows 11（.NET 10 ランタイムが必要）
- 対応ファイル形式: `.m4a` `.flac` `.mp3` `.aif` `.aiff`

### 起動

通常の起動:

```bash
dotnet run --project src/MusicTagAuditor.App/MusicTagAuditor.App.csproj
```

**前回開いていたライブラリは記憶されます。** 2 回目以降の起動では、そのフォルダを自動で開いてスキャンまで行うので、「フォルダを開く...」を押し直す必要はありません。

- 別のライブラリを扱いたいときは、これまでどおり「フォルダを開く...」で選び直してください。以後はそちらを記憶します
- 記憶しているフォルダが見つからないとき（外付けドライブを外している場合など）は、ステータスバーにその旨が出るだけで何も開きません。記憶は消えないので、ドライブを繋ぎ直して起動すればまた開きます
- 引き継がれるのはフォルダのパスだけです。検査結果や保留中の手編集は持ち越されません

起動時に対象フォルダを指定する場合（第1引数にライブラリのパスを渡すと、記憶しているフォルダより優先して、起動直後にそのフォルダを開いてスキャンします）:

```bash
dotnet run --project src/MusicTagAuditor.App/MusicTagAuditor.App.csproj -- "D:\Music\Classic"
```

配布された実行ファイル（`.exe`）がある場合は、それをダブルクリックするか、エクスプローラーで対象フォルダのショートカットにドラッグ＆ドロップしても同様に開けます。

### データの保存場所

| 内容 | 場所 |
|---|---|
| ログ（日次） | `%LOCALAPPDATA%\MusicTagAuditor\logs\` |
| 設定（`settings.json`／バックアップ先・前回のライブラリ）・正規化辞書（`dictionary.json`） | `%APPDATA%\MusicTagAuditor\` |
| タグのバックアップ | 既定はライブラリ直下の `backup_{取得日時}\` フォルダ。「バックアップ先」で変更できる |

正規化辞書（`dictionary.json`）は初回起動時にアプリ同梱の既定辞書からコピーされます。以後は利用者が育てていくものです（詳しくは [8. 辞書タブ](#8-辞書タブ)）。

## 3. 画面の全体構成

メインウィンドウは次の構成です。

```
┌───────────────────────────────────────────────────────────────┐
│ [フォルダを開く...] [再スキャン] [中止]   D:\...\Classic       │
│ [変更...] [既定に戻す]                    （バックアップ先）   │
│ [検査] [バックアップ]  ☐ 発音区別符号も検査                    │
├───────────────┬───────────────────────────────────────────────┤
│ フォルダ       │ [検査結果][辞書に無い値][ファイル一覧][辞書]  │
│ ツリー         │ [バックアップ履歴][読み取り失敗]              │
│               │                                                │
│               │        （選択中のタブの内容）                  │
│               │                                                │
├───────────────┴───────────────────────────────────────────────┤
│ 進捗バー / ステータステキスト                                   │
└───────────────────────────────────────────────────────────────┘
```

### 共通入力エリア（すべてのタブで常に表示される）

| 操作 | 内容 |
|---|---|
| フォルダを開く... | ライブラリのルートフォルダを選び、スキャンする |
| 再スキャン | 現在開いているフォルダを読み直す |
| 中止 | スキャン・検査を中断する |
| 変更...（バックアップ先） | タグのバックアップを置くフォルダを選ぶ。別ドライブでもよい。選んだ内容は設定に保存され、次回以降も使われる |
| 既定に戻す（バックアップ先） | バックアップ先を未指定（ライブラリ直下）に戻す |
| 検査 | 開いているライブラリ全体に検査ルールを適用し、結果タブへ反映する |
| バックアップ | 検査・適用を行わずに、今のタグ状態を手動でスナップショットする |
| 発音区別符号も検査 | 既定で無効な R-304（曲名中のウムラウト欠落）を有効にするチェックボックス |

### 左ペイン: フォルダツリー

ライブラリの階層をツリーで表示します。フォルダを選ぶと、[ファイル一覧タブ](#7-ファイル一覧タブ手編集)がそのフォルダ配下に絞り込まれます（ルート選択時はライブラリ全体が対象）。

[検査結果タブ](#5-検査結果タブ)は既定では追随しません。追随させたいときは、検査結果タブの「選択フォルダのみ」にチェックを入れてください（[選択フォルダで絞り込む](#選択フォルダで絞り込む)）。他のタブ（辞書に無い値・辞書・バックアップ履歴・読み取り失敗）はツリーの選択に関係なく常にライブラリ全体が対象です。

### 右ペイン: 6つのタブ

| タブ | 役割 |
|---|---|
| 検査結果 | ルールが検出した違反の一覧・差分プレビュー・適用 |
| 辞書に無い値 | 修正案を出せなかった値をまとめて確認し、辞書に登録する |
| ファイル一覧 | 全ファイルのタグを表形式で見る・手で編集する |
| 辞書 | 正規化辞書（作曲家・人物・団体・作品・個別例外・誤記・保護対象）の編集 |
| バックアップ履歴 | 過去のスナップショットの確認・復元 |
| 読み取り失敗 | タグを読み取れなかったファイルの一覧 |

## 4. 基本的な使い方（一連の流れ）

典型的な作業はこの順番で行います。

1. **フォルダを開く** — 「フォルダを開く...」でライブラリのルートを選ぶ。自動でスキャンが始まる
2. **検査を実行する** — 「検査」ボタンを押す。24件の検査ルールがライブラリ全体に適用される
3. **検査結果タブで差分を確認する** — ルール別の集計から気になる行を選び、下段の差分プレビューで「変更前 → 変更後」と「根拠」を確認する
4. **チェック状態を確認する** — 既定でチェックが入っている行は「修正値が一意に決まる」もの。チェックが外れている行は人間の判断が必要なもの。安易に全チェックしない
5. **チェックした項目を適用する** — 「チェックした項目を適用」を押す。適用の直前にタグの自動バックアップが取られ、書き込み後は全項目を読み戻して照合される
6. **結果を確認する** — 成功件数・失敗件数・不一致件数が表示される。失敗・不一致があれば一覧で内容を確認する

これを繰り返しながら、辞書に値を登録したり（[6. 辞書に無い値タブ](#6-辞書に無い値タブ)）、アルバム名の保留行から作品や個別例外を足したり（[5. 検査結果タブ](#5-検査結果タブ)の「作品を辞書に追加」「このアルバムの扱いを決める」）、手作業でしか埋められない項目を編集したり（[7. ファイル一覧タブ](#7-ファイル一覧タブ手編集)）して、ライブラリ全体の状態を少しずつ改善していきます。**一度の検査ですべてが片付くことは想定していません。**

## 5. 検査結果タブ

### 選択フォルダで絞り込む

上段のボタン列にある「選択フォルダのみ」にチェックを入れると、左のツリーで選んでいるフォルダ配下の検出だけが対象になります。作曲家フォルダを1つずつ潰していきたいときに使ってください。

**このチェックは既定で外れています。** ツリーはファイル一覧タブの操作にも使うため、フォルダを選んだだけで検査結果が黙って狭まると、全体を見ているつもりのまま作業してしまうためです。チェックを入れないかぎり、検査結果は常にライブラリ全体を出します。

チェックを入れると、次のすべてが同じ範囲に揃います。

| 対象 | 絞り込み中の挙動 |
|---|---|
| 上段のルール別集計 | 「検出」「修正可」「保留」が配下だけの件数になる。配下に検出が無いルールは行ごと消える |
| 下段の差分プレビュー | 配下の明細だけを表示する |
| 「全選択」「全選択解除」「選択反転」（上段・下段とも） | 配下の明細だけに作用する |
| 「チェックした項目を適用」 | **配下の項目だけを書き込む** |
| 「CSV出力」 | 2つのファイルとも配下の分だけを書き出す |

要約テキストの末尾には対象フォルダが `（バッハ 配下）` のように出ます。適用の確認ダイアログにも `対象フォルダ: バッハ（配下のみ）` が表示されるので、書き込む直前に範囲を確認できます。

覚えておいてほしい点が3つあります。

- **範囲外の項目のチェック状態は変わりません。** 絞り込みを外せば、それまでの選択がそのまま戻ります
- **絞り込み中に適用すると、範囲外のチェック済み項目は書き込まれません。** 残りを適用したいときは、チェックを外すか別のフォルダを選んでからもう一度「チェックした項目を適用」を押してください
- ツリーの**ルート**（ライブラリ名の行）を選んでいるときは、チェックが入っていても全体が対象になります

### 上段: ルール別集計グリッド

検査で検出された内容が、ルールごとに1行で集計されます。

| 列 | 内容 |
|---|---|
| 適用 | チェックボックス。チェックした行が「チェックした項目を適用」の対象になる |
| 重大度 | `エラー` / `警告` / `要確認` / `手編集` の文字ラベルで表示（色分けあり） |
| ID | ルールID（`R-101` など。[11. 検査ルール一覧](#11-付録-検査ルール一覧24件)を参照） |
| 検出 | 検出件数 |
| 修正可 | このルールが自動で修正値を出せるか |
| 保留 | 保留（`HOLD_ERA_UNKNOWN` 等）として適用対象外になっている件数 |
| 内容 | ルールの説明 |

行を選ぶと、下段の差分プレビューにそのルールの明細が表示されます。

グリッド上部の「全選択」「全選択解除」「選択反転」は、**表示されている全ルールの明細**に対して一括で操作します。「選択反転」は行単位の一括トグルではなく、明細1件ずつのチェック状態を個別に反転します（一部だけチェックしていた場合、チェックしていたものは外れ、外れていたものが入ります）。

ルール行のチェックボックスは、そのルールの明細が**すべてチェックされているとき**だけチェック状態になります。明細を1件でも外すと、ルール行のチェックは外れます（このとき他の明細は影響を受けません）。

**修正案を出せない項目（「修正可」列が 0 のルール）は、チェックボックス自体が操作できません**（薄く表示されます）。チェックを入れても適用されないため、はじめから選べないようにしています。このようなルールでは、一括操作のボタンも押せない状態になります。

### 下段: 差分プレビュー

| 列 | 内容 |
|---|---|
| 適用 | チェックボックス。チェックした行が「チェックした項目を適用」の対象になる |
| 区分 | 確定 / 要確認 / 保留（行の色分けにも対応） |
| パス | 対象ファイル |
| タグ | 対象フィールド（`composer` など） |
| 変更前 | 現在の値 |
| 変更後 | 修正案の値 |
| 根拠 | なぜその値になったか（例:「フォルダ名から特定」「辞書の正規形は◯◯」） |

グリッド上部の「全選択」「全選択解除」「選択反転」は、**今表示されている（選択中のルールの）明細だけ**に作用します。他のルールの明細には影響しません。

上段と同じく、**修正案を出せない行（「変更後」列が空の行）はチェックボックスが操作できません。** 「この行は自動では直せない」という意味なので、手で直したい場合は行をダブルクリックしてファイル一覧タブへ移動してください。

**根拠列は必ず確認してください。** 自動判定の理由が読めない変更を、内容を見ずに適用しないでください。明細行のチェックは1行ずつ付け外しできます。ただし**チェックの既定値には意味があります**（下記「既定チェック状態」）。外すのは安全側ですが、付けるときは根拠列を読んでその1行を自分で引き受ける、というつもりで操作してください。

列が画面幅に収まらない場合は横スクロールバーが出ます。列の境界をドラッグすれば幅を変えられます。それでも入り切らない長い値は、セルにマウスを乗せるとツールチップで全文が読めます。

### チェック済みの行だけを表示する

下段のボタン列にある「チェック済みのみ」にチェックを入れると、**適用チェックを付けた行だけ**が表示されます。検出が数百件あるルールで、これから書き込む内容を最後に見直すときに使ってください。

**これは表示だけの絞り込みです。** 隠れるのは「適用されない行」だけなので、次のものは何も変わりません。

- 上段の「検出」「修正可」「保留」の件数
- 「チェックした項目を適用」で書き込まれる内容
- 「CSV出力」の内容
- 隠れた行のチェック状態（絞り込みを外せばそのまま戻ります）

絞り込んでいるあいだは、件数表示の「選択 N 件」と画面に並ぶ行数が一致します。この状態で行のチェックを外すと、その行は一覧から消えます（消えるのは表示だけで、明細そのものは残ります）。「全選択」「全選択解除」「選択反転」は**表示されている行ではなく、選択中ルールの明細全体**に作用する点に注意してください。「全選択解除」を押すと一覧は空になります。

「選択フォルダのみ」と併用できます。その場合は「選択フォルダ配下の、チェック済みの行」だけが表示されます。

### 行をダブルクリックしてファイル一覧へ飛ぶ

「この行は自動修正案が出せないので手で直したい」というとき、明細行を**ダブルクリック**すると[ファイル一覧タブ](#7-ファイル一覧タブ手編集)へ切り替わり、そのファイルの行が選択された状態になります。

- 左のツリーは、そのファイルが入っているフォルダを展開して選択し直します
- ファイル一覧側の絞り込み（検索文字列・「空欄のある行のみ」・「編集した行のみ」）で対象行が隠れてしまう場合は、**隠している条件だけ**が解除されます。何を解除したかはステータスバーに出ます
- 再スキャンでファイルが消えているなど、一覧に該当行が無い場合は切り替わらず、理由がステータスバーに出ます

### 「チェックした項目を適用」の既定チェック状態

チェックの既定値は**重大度では決まりません**。「修正値が一意に決まるかどうか」で決まります。

| 状態 | 既定 | 判定区分 |
|---|---|---|
| エラーまたは警告で、修正値が一意に決まる | チェック済み | 確定 |
| 修正値を一意に決められない（重大度に関わらず） | 未チェック | 要確認 |
| 要確認（自動修正しないルール） | 未チェック | 要確認 |
| 保留（収録時点の団体名が `date` 未入力で決められない、等） | 未チェック・適用対象外 | 保留 |

たとえば「エラー」に分類されるルールでも、修正値を一意に決められないケース（指揮者が誰か特定できない等）は既定でチェックされません。逆に「警告」でも、値が一意に決まるもの（`genre` を `Classic` に統一する等）は既定でチェックされます。**重大度の色だけで適用可否を判断しないでください。**

### 件数表示とボタンの活性

ボタンの右には現在の件数が出ます。

| 表示 | 内容 |
|---|---|
| 検出 | 検出された項目の総数。「選択フォルダのみ」がチェックされているときは、選択フォルダ配下の総数 |
| 選択 | 今チェックが入っている項目の数。**検査直後は「既定で選択」と表示される** |
| 保留 | 保留として適用対象外になっている項目の数 |

絞り込み中は末尾に `（バッハ 配下）` のように対象フォルダが付きます。件数だけが減っていると、検査をやり直したのか絞り込んだのかが読み取れないためです。

**チェックを付け外しすると、選択件数はその場で更新されます。** 「チェックした項目を適用」は選択が1件以上あるときだけ押せるので、既定で選択が0件だった検査結果でも、明細を自分でチェックすれば適用に進めます（検査をやり直す必要はありません）。逆に全部外すとボタンは押せなくなります。

上段のルール行のチェックを操作した場合も、下段の明細のチェックと件数の両方がその場で追従します。

### 適用後、検査結果はどうなるか

**「チェックした項目を適用」を実行しても、検査結果タブは空になりません。** 適用に成功した項目だけが一覧から消え、それ以外（チェックが外れていた項目・書き込みに失敗した項目・読み戻し照合で不一致だった項目・修正案が競合した項目）はチェック状態を保ったまま残ります。続けて別の項目にチェックを入れ、もう一度「チェックした項目を適用」を押せます。

ファイル一覧タブの内容は、書き込んだタグの値を反映するため自動的に読み直されます。

### CSV出力

検査結果タブの「CSV出力」で、検査結果を2つのファイルとして書き出します（ファイル一覧タブにも別の「CSV出力」があります。[7. ファイル一覧タブ（手編集）](#7-ファイル一覧タブ手編集)を参照してください）。

| ファイル | 内容 |
|---|---|
| `MusicTagAuditor-changes-{日時}.csv` | 全ルールの差分明細（根拠列を含む） |
| `MusicTagAuditor-changes-{日時}-summary.csv` | ルール別の検出・適用予定・保留の件数 |

Excelでそのまま開けるよう BOM付き UTF-8 で書き出されます。

「選択フォルダのみ」がチェックされているときは、2つのファイルとも選択フォルダ配下の分だけを書き出します。画面の件数と CSV の行数が食い違わないようにするためです。書き出したあとのステータスバーには件数と対象フォルダが出ます。

### 「選択行を辞書に追加」

差分明細で選択した行を、そのまま辞書登録ダイアログに渡せます。開くダイアログは [6. 辞書に無い値タブ](#6-辞書に無い値タブ)の「辞書に追加」と同じものです。

### 「作品を辞書に追加」

アルバム名（R-504）が「作品名を決められない」として保留になっている行から、その作品を辞書に登録します。**アルバム名を組み立てるには作品名が要り、その供給元は辞書の作品エントリだけです。** ここから足していくのが本来の使い方で、辞書タブで手入力するためのものではありません。

ダイアログには次が出ます。

| 項目 | 内容 |
|---|---|
| 作曲家 | そのアルバムから決まっているので**固定表示**です（選び直せません） |
| 作品名 | **空欄で出ます。ここは自分で入れてください。** 現在の `album` の値は誤っていることがあるため、アプリが勝手に採用しません |
| 候補 | 作品名の候補がボタンで並びます。**押すと上の欄に入ります**（そのあと手で直せます）。押さないかぎり何も入りません |
| 別名の候補 | そのアルバムの `album` の値とフォルダ名（演奏者を落とした形も）が、**チェック済み**で並びます。要らないものはチェックを外してください |
| その他の別名 | 候補に無い表記を1行1件で足せます。日本語を含むものは日本語表記として登録されます |

作品名は「ジャンル名は英語、固有の題名は原語」で書きます（`Symphony No. 8` / `Die Walküre` / `The Nutcracker`）。版の違い（ハース版・ノヴァーク版など）でエントリを分けないでください。

候補には出所が添えられます。`album` 由来のものは**現在のタグの値から作った候補**なので、タグ自体が間違っていればその候補も間違っています。`この作曲家の作品` は既に辞書にある作品名で、これを選ぶと新しい行は作られず、選んだ別名だけがその作品に足されます。`辞書の書式` は辞書にある他の作品名の書き方に番号を当てはめたものです。

**`album` とフォルダ名が別の番号を指している場合は警告が出ます**（`album` は 8 番・フォルダ名は 9 番、など）。どちらかのタグが間違っているということなので、候補を選ぶ前に実物がどちらの曲かを確かめてください。

**1つのアルバムに作曲家が複数入っている行では、このボタンは押せません。** 作品を足しても保留は解けないためです。その場合は次の「このアルバムの扱いを決める」を使ってください。

### 「このアルバムの扱いを決める」

アルバム名（R-504）の「作品が決まらない」保留行、**年が割れている「年が決まらない」保留行**、アルバム名の混在（R-501）の明細から、**そのアルバムだけの例外**を登録します。フォルダとディスク番号は明細から自動で埋まるので、パスを手で打つ必要はありません（打ち間違えても例外が黙って効かなくなるだけなので、手入力させない作りにしています）。

同じダイアログで2つの扱いを選べます。

| 選択 | 使う場面 |
|---|---|
| アルバム名の対象外にする | 本物のコンピレーション（1枚に別々の作曲家の作品が入っていて、主となる作品を決められない） |
| 作曲家・作品名・年を指定する | 版の違いで別のアルバム名にしたい / 同一演奏の別リリースを区別したい / 主作品＋併録曲で主作品の作曲家や録音年を教えたい |

**理由の入力は必須です。** 理由の書いていない例外は、後から見たときに消してよいか判断できなくなるためです。

「このフォルダの全ディスクに適用する」にチェックを入れると、ディスク番号の指定を外してフォルダ全体に効かせられます。既定は選択した行のディスクだけです。

登録すると辞書が保存され、自動で再検査されます。**対象外にしたアルバムは、検査結果の一覧から消えます。**

#### 年を指定する（主作品＋併録曲）

主作品と併録曲が別のセッションで録音されていると、1枚のアルバムなのに年が割れます（交響曲第6番 1971 + 序曲2曲 1972 など）。この場合、**フォルダを分けるのも年を揃えるのも誤りです** — 分ければ1枚のアルバムが2つに割れ、揃えればタグが実際の録音年と食い違います。**主作品の録音年を選んでください**（TAGGING_POLICY 3.5 規則2・規則5）。

- **選べるのはそのアルバムに実際に入っている年だけです。** 手で打てないのは、どのファイルにも無い年をアルバム名が名乗らないようにするためです
- **タグの年が1つに揃うと、ここでの指定は使われなくなります。** あとでタグを直したときに、辞書の古い指定が生き残らないようにしています
- 年が割れていないアルバムでは、この欄は出ません

**「演奏者が決まらない」保留行と、年が1つも入っていない行では、このボタンは押せません。** 個別例外に `artist` は書けず、年は「入っている値から選ぶ」しかできないためです。押せてしまうと、タグが割れたまま検査結果から消えた単位ができます。直し方は[保留になる 3 つの場合](#保留になる-3-つの場合)を見てください。

押せないボタンにマウスを載せると、押せない理由が出ます。これは「作品を辞書に追加」も同じです。

## 6. 辞書に無い値タブ

検査ルールが「辞書に登録されていないため修正値を決められなかった」値を、**値単位**でまとめて表示します（同じ値が複数ファイルにまたがっていても1行にまとまります）。

| 列 | 内容 |
|---|---|
| 件数 | 同じ値を持つファイル数 |
| 値 | 実際にタグへ入っている値 |
| 登録先 | 作曲家 / 人物 / 団体のどれとして登録できそうか |
| フィールド | 検出されたタグ項目 |
| ルール | 検出したルールID |
| 代表ファイル | 例として1件のファイルパス |

行を選んで「辞書に追加」を押すと、ダイアログが開きます。

### 辞書に追加ダイアログ

1. 種別を選ぶ（作曲家 / 人物 / 演奏団体）
2. 登録方法を選ぶ（既存エントリの別名にする／新しいエントリを作る）
3. 「辞書に追加して再検査」を押す

登録すると辞書ファイルが保存され、**自動で再検査**されます（ライブラリの再スキャンは行われません。直近のスキャン結果に新しい辞書を当て直すだけなので高速です）。

**推測で名前を登録しないでください。** 誤った正規形を登録すると、誤った修正案がライブラリ全体に広がります。実際にライブラリに存在する値・原則の表に載っている値だけを登録してください。

## 7. ファイル一覧タブ（手編集）

全ファイルの現在のタグを表形式（ファイル / フォルダ / 形式 / タイトル / 作曲家 / アーティスト / 指揮者 / アルバムアーティスト / アルバム / ジャンル / 年 / トラック / ディスク / コメント の14列）で表示します。セルを直接編集できます。

**セルを編集しても、その場ではファイルに書き込まれません。** 編集内容は保留され、差分を確認してから一括で適用します。適用は検査結果タブとまったく同じ経路（自動バックアップ→書き込み→読み戻し照合）を通ります。

### 列幅を変える

14列を1画面に収めきることはできないため、値が長いと末尾が `…` で省略されます。読みたい列は幅を広げてください。

- **見出しの境界をドラッグする** — 列と列の境目にカーソルを合わせると `↔` に変わり、境界線が色付きになります。そのまま左右にドラッグすると、その列だけの幅が変わります
- **見出しの境界をダブルクリックする** — その列の内容が収まる幅に自動で合わせます
- 広げた分だけ表全体が横に伸びます。他の列が押しつぶされることはありません。画面に収まらない部分は下の横スクロールバーで送ってください
- セルにカーソルを重ねると、省略されていない全文がツールチップで出ます。ひとつ確認したいだけならこちらが早いです

**一度でも幅を変えると、ウィンドウを広げたときに列が伸びなくなります。** 初期状態では余った幅がタイトルなどの文字列の列に配分されますが、幅を手で決めた以上その配分は行われません。元の動きに戻したいときは、**見出しを右クリックして「列幅を初期化」**を選んでください。アプリを終了したときも初期状態に戻ります。

### 辞書からの入力候補

作曲家 / アーティスト / 指揮者 / アルバムアーティスト のセルと、一括入力の値の欄では、入力するそばから辞書の候補が絞り込まれて出ます。

- **別名や日本語表記で探せます。** 「ブラ」と打てば `Johannes Brahms` が候補に出ます（どの表記で当たったかも併記されます）
- **確定すると入るのは正規形です。** 上の例なら `Johannes Brahms` が入ります。日本語表記や別名をそのままタグに書くと、次の検査で表記揺れとして指摘されるためです
- 大文字小文字・中黒・ウムラウトの有無は気にしなくて構いません。辞書引きと同じ方法で照合しています

| キー | 動作 |
|---|---|
| ↓ / ↑ | 候補を選ぶ（候補が出ていないときの ↓ は候補を開く） |
| `Enter` | 選択中の候補を確定する。**セル編集では、もう一度 `Enter` を押すとセルが確定します** |
| `Tab` | 候補を確定して次のセルへ移る |
| `Esc` | 候補を閉じる。**もう一度押すとセルの編集を取り消します** |

**候補は入力を助けるだけで、入力を縛るものではありません。** 辞書に無い名前もそのまま入力できます。候補が出ないのは「辞書に登録がない」という意味であって、間違いという意味ではありません。

なお、辞書が扱わない項目（タイトル・アルバム・ジャンル・年・トラック・ディスク・コメント）では候補は出ません。辞書タブで名前を追加して保存すると、その名前はすぐ候補に出てきます。

### コメント欄

版・稿の情報（ハース版／ノヴァーク版など）を書く欄です。決まった書き方はありません。アルバム名には版を含めないため、区別が必要な場合はここに書きます。

同じアルバムの全ファイルに同じ値が入るものなので、**複数行を選んでの一括入力が主な入力手段**になります。あとから探すときは検索ボックスに「ハース版」のように入れてください。コメントも検索の対象です。

**`.mp3` / `.aif` / `.aiff` では扱えません。** これらの形式では、コメントの置き場所が音量正規化などの内部データと同じ場所になっており、書き換えるとその情報を壊すおそれがあるためです。該当する行でコメントを編集すると、下の「気づき」に理由が出ます（編集自体は止めませんが、適用しても書き込まれません）。

### フォルダ欄の `(root)` とエクスプローラーで開く

フォルダ欄には、ライブラリのフォルダから見た相対パスが出ます。**ライブラリのフォルダ直下に置かれているファイルは相対パスにフォルダ部分が無いため、`(root)` と表示されます。** 空欄ではないので、「ルート直下にある」ことと「値が取れていない」ことを取り違えずに済みます。

行を**右クリック**して「エクスプローラーで表示」を選ぶと、そのファイルが選択された状態でエクスプローラーが開きます。ジャケット画像を確認したい、同じフォルダの他のファイルを見たい、といったときに使ってください。行を選択していなくても、右クリックした行が対象になります。

### 絞り込み

- 全列横断の検索ボックス（コメントも対象です）
- 「空欄のある行のみ」— 未入力のタグを探す。**コメントは見ません。** 必要なファイルにしか入れない欄なので、含めるとほとんどの行が該当してしまい、作曲家や指揮者の抜けを探すという目的に使えなくなるためです
- 「編集した行のみ」— これから適用される変更だけを見る

### フォルダ単位の一括入力

指揮者が特定できたときなど、同じ値を複数ファイルにまとめて入れる場合に使います。

1. ツリーでフォルダを選ぶ
2. ファイル一覧で対象の行を選択する（「全選択」ボタン、または一覧にフォーカスがある状態で `Ctrl+A`）
3. 上部で対象フィールドを選び、値を入力して「選択行に一括入力」を押す

「全選択」で選ばれるのは、**そのとき一覧に出ている行だけ**です。絞り込み（検索語・「空欄のある行のみ」・「編集した行のみ」）やツリーのフォルダ選択で隠れている行は選ばれません。フォルダをまたいで直したいときは、まず絞り込みで対象を作ってから「全選択」を押してください。選んだ行数は下部のステータスに出ます。

値を空欄のまま実行すると、そのフィールドのタグを削除します。件数が表示され、確認を求められます。**空欄にすること自体は原則が認める操作です。** 誤った値を入れるより、わからない項目は空欄のままにしてください。

### 適用・破棄

- 「編集内容を適用」— 保留中の手編集をまとめて書き込む（確認・バックアップ・読み戻し照合を経る）
- 「編集を破棄」— 保留中の手編集を取り消す

### CSV出力

「CSV出力」で、ファイル一覧を1つのファイル（`MusicTagAuditor-tracks-{日時}.csv`）として書き出します。絞り込んだ結果を表計算ソフトで確認したいとき、手を入れる前の状態を控えておきたいときに使ってください。Excelでそのまま開けるよう BOM付き UTF-8 で書き出されます。

書き出されるのは、**そのとき一覧に出ている行だけ**です。ツリーのフォルダ選択と絞り込み（検索語・「空欄のある行のみ」・「編集した行のみ」）がすべて効いた結果になります。画面の行数と CSV の行数が食い違わないようにするためです。ステータスバーには書き出した件数と全件数が `（120 件 / 全 1,872 件）` のように出るので、絞り込んだ結果なのかどうかを確かめられます。

値は**画面に見えているとおり**、つまり保留中の手編集を反映したものです。まだファイルには書き込まれていない状態なので、編集した行は「編集」列に `○` が付きます。「複数値」列の `○` は、そのファイルのどれかのタグが複数値として格納されていることを表します（画面では行の色で示しているものです）。

検査結果タブの CSV出力と違い、集計ファイルは出ません。

### 手編集で出る「気づき」

手編集した内容についても検査は行われますが、**処理を止めることはありません。** 出るのはすべて「気づいてほしい点」で、最終判断は人間に委ねられます。

| 気づきの内容 |
|---|
| 値に `;` が含まれる（AIMPが保存時に分割してしまう） |
| 複数値として格納されているフィールドを編集した（M4Aでは複数値を書き分けられない） |
| 配役情報として保護されている `albumartist` を書き換えた |
| `genre` が `Classic` 以外 / `date` が4桁でない / トラック・ディスクが「番号/総数」形式でない |
| 人名・団体名が日本語表記 / 演奏者欄に作曲家名 / 辞書に無い名前 |
| その形式では扱えない項目を編集した（`.mp3` / `.aif` / `.aiff` のコメントなど。適用しても書き込まれません） |

コメントは自由記述なので、書式や辞書の照合は行いません。ただし `;` の気づきだけは出ます。これは内容の指摘ではなく、AIMPが保存したときに値が2つに割れてしまうという格納上の注意です。

### 検査結果との競合

同じファイルの同じフィールドについて、検査の修正案と手編集の両方が存在する場合は**手編集が優先されます。** 人間が明示的に入れた値のほうが強いという考え方です。ただし競合そのものは要確認一覧に残り、どちらの案が採用されなかったかが分かるようになっています。

## 8. 辞書タブ

正規化辞書（`%APPDATA%\MusicTagAuditor\dictionary.json`）を編集します。7つのサブタブに分かれています。

| サブタブ | 内容 |
|---|---|
| 作曲家 | 正規形・別名・日本語表記 |
| 人物 | 正規形・別名・日本語表記に加え、「指揮者」「ソリスト」の区分 |
| 団体 | 実体ID・正規形・時代分割（収録時期ごとの名称）・別名・日本語表記 |
| 作品 | 作曲家・作品名・別名・日本語表記。アルバム名に入る作品名の供給元 |
| 個別例外 | フォルダ・ディスク・作曲家・作品名・年・対象外・理由。そのアルバムだけの例外 |
| 誤記 | 正規表現パターン・置換後の値・その場で試せるテスト入力欄 |
| 保護対象 | 書き換えを禁止する `albumartist` の値（配役情報など） |

共通のツールバーに「保存」「検証だけ実行」「編集を破棄」「既定辞書から取り込む」「既定辞書として書き出し」のボタンがあります。未保存の変更があるときは「●未保存」のインジケータが表示されます。ツールバーの下には**辞書ファイルのパスと、種別ごとの件数**が出ます。検出結果が想定と違うときは、まずここを見て、意図した辞書を読んでいるかを確かめてください。

### 一覧の並び順

各サブタブの一覧は**名前の昇順**で表示されます（作品は「作曲家: 作品名」、個別例外はフォルダ、誤記はパターン順）。同じ人物が2エントリに分かれていないかを目で確かめるためのものです。

**番号は数として並びます。** `Symphony No. 4` → `No. 5` → `No. 10` → `No. 15` の順で、`No. 10` が `No. 4` より前に来ることはありません（エクスプローラーのファイル名の並びと同じ考え方です）。数字以外の部分は日本語環境の通常の文字列比較なので、アクセント付きの名前（`András Schiff`）も `Alicia` と `Anton` の間という素直な位置に入ります。

- **並べ替えは表示だけです。** ファイルに保存される順序は変わりません（誤記は書かれた順に置換を重ねるため、順序を動かすと結果が変わりえます）
- 追加した行は**一覧の実体としては末尾**に入ります。並び順が反映されるのは次に辞書を読み込んだときです
- 編集中に行が動くことはありません。正規形を打ち替えても、その場では位置は変わりません

### 団体タブ

実体IDは**改名をまたいで同一の団体を指すための識別子**です（時代分割の判定にも使われます。TAGGING_POLICY 5.3.1）。

- **先頭に ISO 3166-1（alpha-2）の国コードを小文字で付けることを推奨します。** 本拠地の国コード
  （`ru-` `uk-` `de-` `us-` 等）＋ハイフン＋団体名を略した識別子、という形です（例: `de-berliner-phil`）
- 検査結果タブの「辞書に追加」ダイアログでは正規形から実体IDの候補が自動入力されますが、これは
  正規形をそのままスラッグ化しただけの値（例: `boston-symphony-orchestra`）で、国コードは付きません。
  **保存前に上記の形へ手で直してください**
- 実体IDは団体ごとに一意である必要があります。空欄・重複は保存時のエラーになります

### 作品タブ

アルバム名（`作曲家: 作品名 - 年/演奏者`）の**作品名の供給元**です。これが無いとアルバム名は組み立てられません。

- **作曲家は一覧から選びます（手入力できません）。** 綴りが辞書の作曲家と1文字でも違うと、その作品は引けなくなるためです
- 作品名は「ジャンル名は英語、固有の題名は原語」で書きます
- **1作品1エントリです。版で分けないでください。** 版だけが違う録音は個別例外で扱います
- 別名には、実際のタグに入っている `album` の値やフォルダ名を入れます。日本語の略称（`ブル8`）も日本語表記に入れておくと引けるようになります

ここでも追加・編集はできますが、**本来の入口は検査結果タブの「作品を辞書に追加」**です。そちらなら作曲家も別名の候補も自動で埋まります。

### 個別例外タブ

そのアルバムだけの例外を並べます。**追加ボタンはありません。** フォルダのパスを手で打たせないためで、追加は検査結果タブの「このアルバムの扱いを決める」から行います。ここでは内容の確認・修正・削除ができます。

- `disc` を空欄にすると、そのフォルダの**全ディスク**が対象になります
- `対象外` にも `作曲家` にも `作品名` にも `年` にもなっていない行は、何も起きない例外です。保存はできますが警告が出ます
- `年` は、そのアルバムで `date` が割れているときだけ効きます。タグの年が1つに揃うと使われなくなります
- `理由` が空の行も警告が出ます。理由の書いていない例外は、後から消してよいか判断できません

### 保存時の検証

**保存前に必ず検証が走り、エラーが1件でもあれば保存できません。** 特に注意すべきは以下です。

| 検出内容 | 重さ |
|---|---|
| 別名の正規化キーが他のエントリと衝突 | エラー（保存不可） |
| 実体IDの重複・空欄 | エラー |
| 正規表現として解釈できないパターン | エラー |
| 未知の役割名、正規形が空 | エラー |
| 作品の作曲家が空、または辞書の作曲家と一致しない | エラー |
| 同じ作曲家に同じ作品名が2つある / 同じ作曲家の中で別名が衝突 | エラー |
| 個別例外のフォルダが空 / 年が4桁でない | エラー |
| 時代分割の期間の重なり・隙間 | 警告（保存は可能） |
| 同一エントリ内での別名の重複 | 警告 |
| 種別をまたいだ同名 | 警告 |
| 個別例外の理由が空 / 何も起きない個別例外 | 警告 |

**正規化キーの衝突は特に見えにくい失敗です。** 既存エントリと同じ正規化キー（NFKC・小文字化・ひらがな→カタカナ変換・発音区別符号除去・記号と空白の除去を経た比較用の値）を持つ別名を登録しようとすると、保存前の検証で止まります。「登録したのに効かない」という状態を避けるための仕組みなので、保存できない場合はまずこのエラーを疑ってください。

保存すると一時ファイル経由で本体が差し替えられ、直前のバージョンが `dictionary.json.bak` として残ります。

**検証結果の行をクリックすると、その問題のエントリが開きます。** 種別タブが切り替わり、該当の行が選択された状態までスクロールします。作品のように件数が多い一覧でも、警告を上から順に潰していけます。

- 絞り込みをかけている場合、**対象を隠しているときだけ**外れます。当たっている絞り込みはそのまま残ります
- 検証したあとに名前を書き換えていると見つかりません。その場合は「検証だけ実行」でやり直してください

検証結果は画面下部の枠に出ます。右上の**「閉じる」**で消せます。消えるのは表示だけで、問題が解決したわけではありません（エラーがあれば保存は止まったままです）。「検証だけ実行」または保存でいつでも出し直せます。時代分割の隙間のように、承知のうえで残す警告が居座る場合に使ってください。

### 「既定辞書から取り込む」

アプリに同梱されている既定辞書側だけに存在する内容を、利用者の辞書に取り込みます。**利用者の辞書は初回起動時にコピーされたきり自動更新されません。** 取り込める差分がある場合は起動時に件数が表示され、ボタンが強調されます。

取り込めるのは次の内容で、**すべて追加のみ**です（削除や上書きはされません）。

| 取り込む内容 |
|---|
| 既定辞書にしか無いエントリ（作曲家・人物・団体・誤記・保護対象） |
| 既存エントリに足りない別名 |
| 既定辞書で新しく立った設定（`noConductor` / `noEraSplit`） |

ボタンを押すとダイアログが開き、取り込み候補が一覧で表示されます。1件ずつチェックを外せるので、意図せず復活させたくない項目は事前に外してください。

**取り込みは追加だけです。既定辞書から別名が消えても、この操作では消えません。** 手元の辞書に溜まった不要な別名は、次の「冗長な別名を掃除」で片付けます。

### 「冗長な別名を掃除」

**書いてあるのに引かれていない別名**をまとめて削除します。

辞書の照合は、大文字小文字・記号・ダイアクリティカルマーク・濁点を落とした「正規化キー」で行います。そのため次の組はすべて同じキーになり、**先に書いたほうしか索引に載りません。**

| 例 | 畳まれる理由 |
|---|---|
| `Antonín Dvořák` と `Antonin Dvorak` | ダイアクリティカルマークが落ちる |
| `Symphony No. 7` と `Symphony No.7` | 記号と空白が落ちる |
| `ウェーバー` と `ヴェーバー` | 濁点が落ちる |

後から書いたほうは登録しても効かず、検証の警告として残り続けます。**削除しても引ける値は変わりません**（残る名前で今までどおり引けます）。

ボタンを押すとダイアログが開き、消える別名と、代わりに残る名前が一覧で表示されます。内容を確認して「掃除して保存」を押すと、削除して保存まで行います。取り込みと違って1件ずつ選ぶチェックはありません。並んでいるのはいずれも索引が既に捨てているもので、残す理由が無いためです。

正規形と、団体の時代分割の名前は削除しません。これらは別名ではなく、消すと引けなくなります。

### 「既定辞書として書き出し」

育てた辞書をリポジトリ同梱の既定辞書ファイルへ書き戻す機能です。**これは開発者向けの機能で、通常のライブラリ整理では使いません。** 誤って押さないよう注意してください。

## 9. バックアップ履歴タブ

### 自動バックアップの仕組み

検査結果タブ・ファイル一覧タブのどちらから適用する場合でも、**適用の直前に必ず自動でタグのスナップショットが取られます。** 利用者が明示的にバックアップを取っていなくても保護されます。音声ファイル本体は複製されず、タグの内容だけが JSON として保存されます。

保存先は `backup_{取得日時}\` フォルダで、次のファイルを含みます。

| ファイル | 内容 |
|---|---|
| `tags_snapshot.json` | 全ファイルの全タグ。復元はこの内容を使う |
| `manifest.json` | 取得日時・理由・件数 |
| `restore-tags.ps1` | アプリを使わずに復元するための PowerShell スクリプト |

### バックアップ先を変える

既定ではライブラリ直下に置かれます。音楽フォルダを汚したくない場合や、別ドライブへ退避しておきたい場合は、入力エリアの「バックアップ先」の「変更...」で任意のフォルダを選んでください。「既定に戻す」で未指定（ライブラリ直下）に戻ります。

- 選んだフォルダに書き込めない場合は、ステータスバーに理由が出て設定は変わりません
- **保存先を変えても、前の場所に取ったバックアップは履歴に残り続けます。** この一覧は設定した保存先とライブラリ直下の両方を見ています
- 1 つの保存先を複数のライブラリで共用できます。履歴には、いま開いているライブラリのものだけが出ます
- 保存先をライブラリの中に置いても、その中の音声ファイルはスキャン対象になりません

### 復元

一覧からスナップショットを選び、「差分を確認」で何が変わるかを見てから、「選択した項目を復元」で書き戻します。**内容を確認せずに復元しないでください。**

**コメント欄に対応する前に取ったバックアップからは、コメントは復元されません。** そのときのバックアップにはコメントが記録されておらず、「もともと空だった」のか「記録していなかった」のかを区別できないためです。区別できないまま戻すと、今入っている注記を消してしまいます。コメント以外の項目は通常どおり復元されます。

### アプリを使わない復元（上級者向け）

アプリを起動できない状況でも、PowerShell から直接復元できます。

```bash
pwsh -File "D:\Music\Classic\backup_20260803031500\restore-tags.ps1" -DryRun
```

`-DryRun` を付けると実際には書き込まず、変更内容の確認だけを行います。実際に書き戻すときは `-DryRun` を外してください。`-PathFilter` オプションで対象フォルダを絞り込むこともできます。PowerShell 7 以降が必要です。

バックアップ先を変えている場合は、そのフォルダの中の `backup_{取得日時}\restore-tags.ps1` を指定してください。**復元先はスナップショットに記録されたライブラリのパスから決まる**ので、スクリプトがライブラリの外にあっても正しく書き戻されます。

### 既定でチェックしないルールの補足

- **R-303**（ファイル名からの曲名補完）: ファイル名にはWindowsで使えない文字の代替が混じっていることがあり、元が何だったか機械的に決められません。先頭のトラック番号だけを落とした値を修正案として出しますが、既定ではチェックされず、判定区分は「要確認」です
- **R-403**（文字化けの削除）: 復元すると多くの場合「アーティスト情報なし」等の実質的な未設定状態になります。消すか入れ直すかは人間が判断すべきため、既定ではチェックされません
- **R-304**（曲名中のウムラウト欠落）: CD原盤が意図的にASCII表記である可能性があり、誤検出が増えるため既定で無効です。ツールバーの「発音区別符号も検査」で有効にできます。有効にしても自動修正はされず、候補を示すのみです
- **R-210**（`composer` と違う作曲家名）: `composer` の値が辞書の正規形として正しいのに、そのファイルの作曲家ではない場合があります。演奏会1回分のプログラムが1フォルダに入っていて、全曲が主作品の作曲家で埋められている、といった状態です。値そのものは正しい形をしているため他のルールでは検出できず、手掛かりはファイル名・曲名・フォルダ名に出てくる作曲家名しかありません
  - フォルダ名は**フォルダ内の `composer` が1種類のときだけ**手掛かりにします。1枚に複数の作曲家が入っているカップリング盤では、フォルダ名は主作品の作曲家を名乗るため、併録曲が「フォルダ名と違う作曲家」になるのが正しいからです
  - **一致しても誤りとは限りません。** ブラームス『ハイドンの主題による変奏曲』のように、曲名が別の作曲家の名前を正当に含む作品があります。この判別は機械にはできないため、修正案を出さず、既定でもチェックされません
  - **辞書に載っている作曲家名しか検出できません。** 上のハイドンは現在辞書に無いため検出されませんが、ハイドンの録音を所蔵して辞書に足すと誤検出に変わります。**辞書が育つほど誤検出は増える**性質のルールです
  - `composer` が空欄のファイルは対象外です（R-401 が扱います）

### アルバム名の付け替え（R-504）

アルバム名は `{作曲家}: {作品名} - {date}/{artist}` の形にそろえます（`TAGGING_POLICY.md` 3.5）。

```
Anton Bruckner: Symphony No. 8 - 1993/Günter Wand
```

判定は**アルバム単位（フォルダ + ディスク番号）**で行い、同じアルバムのファイルには同じ名前を出します。1枚が複数ディスク・複数フォルダに分かれていても同じ名前になります。

**`{作品名}` は辞書の「作品」に登録した名前から取ります。** 曲名は楽章名、`album` は `Symphony No.5` のような汎用名なので、どちらからも作品名は決まらないためです。**作品を登録していないアルバムは保留になります。**

#### 保留になる 3 つの場合

保留は「今は決められないが、条件が揃えば自動的に判定し直せる」状態です。適用の対象外で、チェックもできません。

| 表示 | 意味 | 解消するには |
|---|---|---|
| 作品が決まらない | 辞書に作品が無い／`album` とフォルダ名が別の作品を指す／1枚に複数の作曲家がいる | 保留行を選んで「作品を辞書に追加」、`composer` を直す、「このアルバムの扱いを決める」 |
| 年が決まらない | `date` が空、またはアルバム内で年が割れている | 空なら CD 実物で録音年を確かめて `date` を入れる。**割れている場合は下の 3 通りを見分けてください** |
| 演奏者が決まらない | `artist` がアルバム内で一意でない | フォルダを分けるか、ファイル一覧タブで `artist` を揃える |

**推測では埋めません。** 最古の年や一番多い年を選ぶようなことはしません。どれも「その録音の年」を表さないためです。

年が割れている場合、直す先は**3 通りあります。** 見分けるのは人にしかできません。

- **別々の録音が 1 つのフォルダに入っていた場合** — フォルダを分けます。アルバム単位はフォルダ + ディスク番号で決まるので、分ければそれぞれの単位で年が一意になります
- **同じ録音で表記だけが割れていた場合** — 保留行を**ダブルクリック**するとファイル一覧タブの当該行へ移動します。そこで正しい値に揃えてから、もう一度検査してください（複数行をまとめて直すには一括入力を使います）
- **主作品と併録曲で録音年が違う場合** — 1枚のアルバムとして正しい状態なので、フォルダも `date` も直しません。保留行を選んで「このアルバムの扱いを決める」を押し、**主作品の録音年**を選びます（[「このアルバムの扱いを決める」](#このアルバムの扱いを決める)）

演奏者の保留は**タグそのものを直さないと解けません。** 「このアルバムの扱いを決める」は押せません（個別例外に `artist` は書けないためです）。

#### 対象外にしたアルバム

1枚に複数の作品が入っていて主となる作品が決まらないもの（名曲集、序曲集、抜粋盤など）は、保留行を選んで「このアルバムの扱いを決める」で対象外にできます（[5. 検査結果タブ](#5-検査結果タブ)）。**対象外にしたアルバムは検査結果に出ません。**「直す必要があるのに出ていない」のではなく「対象外だと決めた」ものだからです。何を対象外にしたかは辞書タブの「個別例外」で確認できます。

#### R-501 / R-502 との関係

R-501（複数の作曲家が混在）と R-502（日本語のアルバム名）は残ります。R-501 は個別例外を書く対象を見つけるため、R-502 は R-504 が直せなかったアルバムを見つけるための一覧です。R-501 の明細からも「このアルバムの扱いを決める」を押せます。

## 12. 付録: タグ付けの原則の要点

検査ルールの背景にある考え方です。詳細は [docs/TAGGING_POLICY.md](TAGGING_POLICY.md) を参照してください。

### フィールドの役割

| フィールド | 入れるもの |
|---|---|
| `composer` | 作曲家 |
| `artist` | その録音の主役（協奏曲はソリスト、室内楽は演奏者・団体、それ以外は指揮者） |
| `conductor` | 指揮者。指揮者がいる録音では `artist` の内容に関わらず必ず入れる |
| `albumartist` | 演奏団体名 |

指揮者を置かない室内楽・独奏・合奏団の録音では、`conductor` が空欄であるのが正しい状態です（→ R-402 が誤って指摘することはありません）。

### 配役情報は保護される

歌手・合唱団の配役が記録されている `albumartist` の値（オペラの全キャスト表記など）は、書き換えると情報が失われるため、辞書上「保護対象」として登録され、すべての検査ルールの対象から除外されます。**保護対象の削除・変更は慎重に行ってください。**

### 区切り文字に `;` を使わない

AIMP はタグの保存時に `;` を複数値の区切りとして解釈し、1つの値を分割してしまいます。連結が必要な場合は `;` でつなぐのではなく、別のフィールドに分けます。

### 空欄は正しい状態でありうる

確信の持てない項目を無理に埋めるより、空欄または現状維持のまま保留にするほうが、あとから正しい情報で対処できます。ファイル一覧タブでの一括入力も、値を空にする操作を正式にサポートしています。

### 収録時点の名称を優先する（団体名）

同じ演奏団体でも、改称や再編があった場合は録音年によって表記が変わります（例: レニングラード・フィルハーモニー管弦楽団 → サンクトペテルブルク・フィルハーモニー管弦楽団）。この同一性は名前の類似度ではなく「実体ID」で判断されるため、名前が似ていても別団体、名前が違っても同一団体という扱いになることがあります。`date` が空欄でどちらの時代の名称か決められない場合は、書き換えずに保留（`HOLD_ERA_UNKNOWN`）になります。

### 画面の項目名と、ファイルに実際に書き込まれるタグ名の対応

[ファイル一覧タブ](#7-ファイル一覧タブ手編集)や検査結果の差分プレビューに出てくる項目名は、アプリ内での呼び名（論理フィールド名）です。実際のファイル内部では、拡張子ごとに異なる名前のタグとして格納されます。他のタグ編集ソフト（AIMP等）で見比べたいときや、値が反映されない原因を調べたいときに参照してください。

| 画面の項目名 | 論理フィールド | M4A（MP4 atom） | FLAC（Vorbis comment） | MP3 / AIFF（ID3v2） |
|---|---|---|---|---|
| タイトル | title | `©nam` | `TITLE` | `TIT2` |
| 作曲家 | composer | `©wrt` | `COMPOSER` | `TCOM` |
| アーティスト | artist | `©ART` | `ARTIST` | `TPE1` |
| 指揮者 | conductor | `©con` | `CONDUCTOR` | `TPE3` |
| アルバムアーティスト | albumartist | `aART` | `ALBUMARTIST` | `TPE2` |
| アルバム | album | `©alb` | `ALBUM` | `TALB` |
| ジャンル | genre | `©gen` | `GENRE` | `TCON` |
| 年 | date | `©day` | `DATE` | `TDRC` |
| トラック | tracknumber | `trkn` | `TRACKNUMBER`（`3/12` のように番号/総数をまとめて1フィールドに格納） | `TRCK` |
| ディスク | discnumber | `disk` | `DISCNUMBER`（同上） | `TPOS` |
| コメント | comment | `©cmt` | `COMMENT` | **扱いません** |

（[docs/TAGGING_POLICY.md](TAGGING_POLICY.md) 4.1・実ファイルとAIMPで検証済み）

**指揮者欄は特に注意が必要です。** MP4/M4A には指揮者を格納する標準の atom が存在しません。`©con` は規格外の4文字 atom ですが、再生環境の AIMP がこれを採用しているため、このアプリも `©con` に書き込みます。M4Aファイルを別のタグ編集ソフトで開いたときに指揮者欄が空に見える、あるいは値が別の場所（`cond` atom 等）に入ってしまっている場合は、この atom の違いが原因である可能性があります。

**`.mp3` / `.aif` / `.aiff` のコメントは、このアプリでは読み書きしません。** ID3v2 という形式では、コメントの置き場所に「説明ラベル」を付けて別のデータも入れられるようになっており、iTunes が音量正規化の情報（`iTunNORM`）などをそこへ書き込みます。ここをコメント欄として扱うと、値を消したときにその情報まで消えてしまい、元に戻せません。他のソフトで `.aif` を開くとコメント欄に見慣れない英数字が並んでいることがありますが、それがこのデータです。この形式のファイルではコメント欄は常に空で表示されます。

## 13. 困ったときは（FAQ）

**Q. 同じフィールドに複数の修正案が競合しています。どちらが採用されますか？**
A. 機械的にどちらが正しいか決められないため、**どちらも書き込まれず**競合として要確認一覧に残ります。CD実物などで確認し、手編集で確定させてください。

**Q. 指揮者欄（`conductor`）が空欄のまま検出されないファイルがあります。バグですか？**
A. 室内楽・独奏曲・指揮者を置かない合奏団の録音では、`conductor` が空欄であるのが正しい状態です。辞書の `noConductor` 設定と演奏者の役割に基づいて判定されているため、意図的に検出対象から外れています。

**Q. M4A（`.m4a`）ファイルで、複数の演奏者名が1つの値にまとまってしまいます。**
A. M4A ではタグライブラリの仕様上、複数値を書き分けて保存できません。書き込み後の読み戻し照合で不一致として検出されるのはこのためです。FLAC / MP3 / AIFF にはこの制約はありません。

**Q. 「適用」の結果に失敗や不一致がありました。何をすればいいですか？**
A. 1件の失敗で処理全体は止まりません。結果画面に出る失敗・不一致の一覧を確認してください。詳細はログ（`%LOCALAPPDATA%\MusicTagAuditor\logs\`）にも記録されます。必要であれば [9. バックアップ履歴タブ](#9-バックアップ履歴タブ)から適用前の状態に復元できます。

**Q. 検査結果に出てくる「要確認」は無視してよいですか？**
A. 無視はできますが推奨しません。要確認になっている項目は「機械的に修正値を決められなかった」ものです。CD実物の確認などで判断がつくものは、手編集で埋めることでライブラリの状態が改善します。
